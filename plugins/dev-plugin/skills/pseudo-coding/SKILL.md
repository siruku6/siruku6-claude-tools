# 擬似コードの書き方

## いつ使うか

- 実装前にロジック変更案を提示し、ユーザーの合意を得るとき
- 既存コードの複雑な制御フローを人間向けに説明するとき

## ルール

- 使ってよい制御構造は `for`・`while`・`if`・`continue`・`break` 程度に限定する
- 処理の内容はコードではなく日本語の概念で記述する（例：`deferred_works.append(work); continue` → 「延期キューへ回してスキップ」）

## 例

以下は、ある処理の変更前後を擬似コードで示す例です。before/after の対比は一例であり、
新規ロジックを単体で提示する場合も同じ書き方を使う。

**例（before）**

```
reset()

for task in 全タスク（優先度順）:
    バッチ処理（トリガー条件を満たす場合）
    タスクの詳細処理を実行
    task を完了待ちリストに登録

残りのバッチ処理をすべて実行
```

**例（after）**

```
reset()

タスク_index = 0

while 全タスクのうち未処理のタスクがある:
    task = 全タスク[タスク_index]
    if メンテナンス期間中:
        日付だけ +1
        continue
    elif 期限直前かつバッチ処理の完了予測が期限超え:
        バッチ処理（必ず実行する）
        日付 +1
        continue

    バッチ処理（トリガー条件を満たす場合）
    task の詳細処理を実行
    task を完了待ちリストに登録

    日付 +1
    タスク_index += 1

残りのバッチ処理をすべて実行
```
